# 第九步：板上刺激和测量接口设计审查

本说明是依据早期 195 MHz 零输入 AXKU115 bitstream 制定的设计草案，保留作为决策记录。实际实现以 `host_protocol.md`、JTAG RTL 与后续板上结果为准：可写刺激版已经改为 200 MHz 和 200000-cycle 周期。本文本身不表示板上数据已测得。

## 已确认的核心语义

- 内核只在 `ST_IDLE` 接受 `start_timestep`，并在该时钟沿锁存有符号 S34.24 的 `input_current`。一次启动只计算一个 1 ms 模型 timestep。
- 同一个电流值只加到 `type_sign_mem[neuron][2]` 标记的 93 个输入锚点。当前接口不能对不同输入神经元分别施加电流，也不能直接接收原始音频。
- 每个放电神经元产生一次 `spike_valid` 与 13 位 `spike_neuron`。输出按神经元索引递增；`spike_is_pC1` 对应同一事件。每个 timestep 结束时 `timestep_done` 脉冲一次，状态/累加器饱和标志对该步锁存。
- `busy` 在计算期间有效。若下一个 `start_timestep` 到来时内核仍忙，请求会被忽略，因此调度器必须显式报告超期并停止，不能悄悄丢失一步。
- 现有 `rst` **不清空** `voltage_mem`、`syn_current_mem`、`refractory_mem`；这三块内存仅在 FPGA 配置后的 `initial` 块中初始化。KEY1 或 JTAG 控制复位后直接运行下一试次会继承上一次的神经元状态。
- 目前只有 pC1 的标志随事件输出。aPN1、vPN1、pIP10、pMP2 等需要由 `type_sign.mem` 的位 5、6、8、9 生成事件分类查找表，或在内核加同步分类端口。

第八步 8 个 timestep 的输入为 `0x001333333` 连续三次，随后五次零；每步放电数为 93、138、322、636、616、346、227、97，总数 2475。`expected_spike.mem` 按 `timestep × 6279 + neuron_index` 展平。板级回读可把每步记录的 `spike_neuron` 恢复为 6279 位 spike 向量，逐位与此文件比对。现有第八步仿真还比较内部电位、电流和 refractory；板级端口没有这些状态的读出，因此仅靠事件回读不能声称完成全部内部状态的板上 bit-exact 对拍。

## 试次前清零握手

给内核增加 `clear_start`、`clear_done`/`state_ready`，在空闲状态进入 `ST_CLEAR`。清理计数器依次访问 0..6278，并在每个时钟沿同时把上述三块状态 RAM 写零。清理需要至少 6279 个 195 MHz 时钟，约 32.2 µs，发生在试次之间。`spike_queue` 无需清零，因为每个新 timestep 都把 `spike_count` 置零。

接受顺序为：硬复位释放 → 清理全部地址 → `state_ready` → 载入/校验刺激长度 → 允许 `start_timestep`。若 KEY1 在计算或清理中按下，控制器复位释放后应从地址 0 重做完整清理。软件 `abort` 也必须令当前状态失效，并在下一次启动前完成清理。`clear_start` 与 `start_timestep` 同时出现时，清理优先。清理期间内核的 `busy` 或独立的 `clear_busy` 必须令调度器禁止启动。不要尝试用一个时钟周期的 `for` 循环清空 RAM，那样无法维持当前 BRAM 实现。

新增清零写地址和写使能会改变 BRAM 的输入路径；当前板级 WNS 只有 +0.074 ns，必须重新运行综合、布局布线、DRC 和 195 MHz 时序验收。也要在仿真中测试“先运行非零刺激、清理、再运行同一刺激”与首次运行逐位一致，以及清理中 KEY1 中止后重新清理。

## 缓冲区与资源预算

建议刺激 RAM 保存最多 8192 个 S34.24 样本，覆盖第四步每组 4308 ms 试次。每个样本按 36 位物理字存储，约用 8 个 RAMB36。结果摘要 RAM 每步 128 位、8192 深，约用 32 个 RAMB36。事件 RAM 为 65536 × 16 位，约用 32 个 RAMB36；可容纳八步比对最坏的 `8 × 6279 = 50232` 个事件。分类 ROM 6279 × 5 位约需 2 个 RAMB36。以上基于 KU115 常见 BRAM 位宽/深度配置，合计估计 74 个 RAMB36；当前固定零输入板级用了 503 个，但动态输入核心约为 504 个，估计增加后约 578 个，低于先前采用的 625 个工程预算。最终数字必须以 Vivado 报告为准；JTAG/AXI 逻辑及布线余量也应留在预算内。

| 存储区 | 深度 × 宽度 | 作用 | 估计 RAMB36 |
| --- | ---: | --- | ---: |
| stimulus | 8192 × 36 | 一个 timestep 一份有符号 34 位电流 | 8 |
| summary | 8192 × 128 | 每步总数、群组数、延迟及标志 | 32 |
| event | 65536 × 16 | 事件按时序连续写入，低 13 位是 neuron index | 32 |
| group ROM | 6279 × 5 | aPN1、vPN1、pC1、pIP10、pMP2 分类 | 2 |

事件 RAM 记录事件时须在 `spike_valid` 当拍或一级流水后写入，不可等到 `timestep_done` 再取内核的 `spike_queue`。每步摘要中的总放电数提供事件边界：主机从累计前缀和切分每步列表。若启用事件捕获且缓冲区达到容量，置 `event_overflow` 并在该步结束后停止 trial；只有摘要仍可信，事件数据不可作为完整轨迹。不能环形覆盖最早事件。

第四步完整试次曾出现超过 12 万个全网事件，65536 深度不足以无中断保存整组原始事件。4308 ms IPI 扫描可关闭全事件捕获，只连续保留每步总数/五类计数；需要完整逐事件数据时分试次或扩展事件 RAM，并明确会暂停或增大存储。JTAG 回读速度不能被假设足以在每个 1 ms 间隙排空放电事件。

建议摘要 4 个 32 位字/步：

| 字 | 位域 | 含义 |
| --- | --- | --- |
| 0 | `[15:0]` / `[31:16]` | 全网 / aPN1 spike 数 |
| 1 | `[15:0]` / `[31:16]` | vPN1 / pC1 spike 数 |
| 2 | `[15:0]` / `[31:16]` | pIP10 / pMP2 spike 数 |
| 3 | `[20:0]`、`[21]`、`[22]`、`[23]`、`[24]` | 本步 cycles、状态饱和、累加器饱和、deadline miss、事件溢出；其余位保留 |

21 位周期字段可容纳到 2,097,151 cycles；超过时应饱和并设置独立计数器溢出状态。16 位放电数字段可容纳单步最多 6279 个事件。群组计数应在同步分类 ROM 的事件流水全部写入后再提交摘要。

## 1 ms 调度与时间测量

195 MHz 下每个模型 timestep 对应准确的 195000 个系统时钟。首次启动时记录 64 位 `trial_epoch`；对第 `t` 步，期望启动边界为 `trial_epoch + t × 195000`。刺激 RAM 要提前读取并稳定在启动沿之前。事件日志、摘要和主机寄存器操作不能给核心插入暂停周期。

在每个边界，若上一 `timestep_done` 尚未到达，或 `busy` 仍为 1，置 `deadline_miss`，待当前步完成后停止试次并报告完成步数。这样不会悄悄跳过输入样本。可另设“完成即启动下一步”的功能对拍模式，但该模式的壁钟时间不代表 1 ms 实时运行。

用板上 64 位自由运行周期计数器记录内核实际接受启动与 `timestep_done` 的边沿，保存每步延迟、最大延迟和超期次数；主机 JTAG 往返时间不进入计算延迟。当前仿真最坏一步为 192784 cycles，折合 988.636 µs，距 195000-cycle 界限仅 2216 cycles。这个数字来自当前无接口核心，新增清零和记录逻辑后必须重新测量；边沿定义及一两周期流水偏差应在新测试平台里锁定。

## 建议的主机可见寄存器

寄存器与存储器均按 32 位 AXI 地址对齐。地址仅为供实现者固定协议的提案；RTL 和主机程序必须共用一份定义，禁止各自手写不一致的常数。

| 偏移 | 名称 | 用途 |
| ---: | --- | --- |
| `0x0000` | ID/VERSION | 固定签名与协议版本；主机下载 bitstream 后先核对 |
| `0x0004` | CONTROL | clear、start、capture_events、realtime、abort 请求脉冲 |
| `0x0008` | STATUS | ready、clearing、running、trial_done、deadline_miss、overflow、fault |
| `0x000C` | STEP_COUNT | 本试次要运行的步数，范围 1..8192 |
| `0x0010` | COMPLETED_STEPS | 已完整提交摘要的步数 |
| `0x0014` | EVENT_COUNT | 已写入 event RAM 的条数 |
| `0x0018` | MAX_CYCLES | 本试次最大步延迟 |
| `0x001C` | DEADLINE_MISSES | 超期次数 |

刺激窗口可映射在 `0x10000 + 8 × t`：低字是 `input_current[31:0]`，高字仅 `[1:0]` 有效，对应 `[33:32]`。写入高字后再将完整 34 位值提交到刺激 RAM；主机在 `start` 前读回或校验写入数量。摘要、事件各用独立地址窗口，避免主机在试次运行中读写与 FPGA 写端口争用。可以把所有读回安排在 `trial_done` 后。主机应在元数据中记录 bitstream SHA-256、IR/固定点协议 hash、输入序列 hash、时钟频率和实际 `COMPLETED_STEPS`。

## 验收顺序

1. 仿真控制器：零长度/越界拒绝、34 位负数编码、精确 195000-cycle 发射、事件流水与步末边界、容量溢出、超期停止、clear 中断与恢复。
2. 八步板级对拍：写入固定的 `stimulus.mem`，清零，运行并读取 2475 个有序事件；按步重建 spike bit 向量，与 `expected_spike.mem` 的 50232 位逐位比较。报告每步事件数、差异数、饱和状态和实际 cycles。若未增加状态扫描口，不宣称板上电位/电流/refractory 已逐位核实。
3. 4308 步 IPI trial：每个条件先清零，再载入相应刺激，事件捕获按容量策略关闭，回读全部 4308 条摘要。先检查 `COMPLETED_STEPS`、超期、饱和与溢出，然后计算群组响应曲线。
4. 对新增板级顶层重新完成 bit-exact 仿真、Vivado 完整布局布线、DRC、195 MHz setup/hold、上板 JTAG 读写与实际回读。只有板上日志齐备后才报告“实测”。
